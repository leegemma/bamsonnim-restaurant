# 밤손님 식당

한옥에서 기괴한 한식을 팔고 좀비 손님을 수집하는 모바일 웹 타이쿤 테스트 게임입니다. 브라우저의 가로 화면에서 터치 또는 마우스로 플레이합니다.

최신 기획과 구현 계획은 [Proposed Plan](docs/PLAN.md), 남은 UI 수정 목록과 검토 근거는 [인터페이스 검토](docs/INTERFACE_REVIEW.md)에 있습니다.

역할별 모델·effort와 협업 기준은 [팀 구성](docs/TEAM.md), 별도 5시간 실행의 상태 확인은 [자동 플레이 기록](docs/AUTOPLAY.md)에 기록합니다.

## 실행

```sh
npm install
npm run dev
```

터미널에 표시되는 `http://127.0.0.1:5173`을 여세요. 정적 배포 파일은 `npm run build`로 생성하며, `npm run preview`로 빌드 결과를 확인할 수 있습니다. 검증은 `npm test`입니다. Node.js 20 이상과 최신 브라우저를 사용합니다.

친구에게 공유할 공개 플레이 주소: https://leegemma.github.io/bamsonnim-restaurant/
GitHub 소스 저장소: https://github.com/leegemma/bamsonnim-restaurant

## 첫 영업

1. 가마솥의 **COOK**을 누르고 뇌 주먹밥을 선택합니다.
2. 12초 후 **DONE**을 누릅니다. 직원이 서빙대로 음식을 운반합니다.
3. 직원이 손님에게 음식을 가져다주고, 식사와 결제가 끝나면 코인과 경험치를 받습니다.
4. 반복 조리로 숙련도를 올립니다. 음식 숙련도 합계가 레시피 레벨이며, 식당 레벨과 별도로 새 메뉴를 엽니다.
5. 접속 중 식사·결제를 마친 새 손님이 캐릭터북에 등록됩니다.

스토브 음식은 방치하면 부패하고 서빙대 음식은 부패하지 않습니다. 자동 재조리는 하지 않습니다. 식당 레벨이 오르면 직원과 설비 한도, 확장 조건과 손님 등장 조건이 열립니다.

## 첫 버전 기능

- 일반 음식 12종, 일반 좀비 **29종**, 크리스마스 음식 2종·특별 손님 2종·장식 3종
- 직원 고용·해고·자동 서빙·정리·직원 운반
- 격자 인테리어 구매·이동·회전·보관·판매, 바닥·벽 변경, 식당 확장
- 허기 게이지·붉은 좀비·직원 감염, 5분 자동 회복과 코인 치료
- 연속 서빙 콤보와 30초 피버, 시장님 의뢰와 보상
- 최대 8시간 오프라인 영업, 실제 시간 조리·부패·회복
- 기기 내 자동 저장, JSON 백업·불러오기, 손상 파일 복구본 보존
- 2분 15초·7개 구간의 자체 합성 레트로 음악과 효과음, 별도 음량 조절
- 요리책에서 잠금 메뉴를 포함해 조리 비용과 재고 1개당 판매가를 따로 확인

**테스트 → 전체 캐릭터·음식 이미지 보기**에서 미발견 캐릭터의 미술 자료도 볼 수 있습니다. 도감 수집 기록은 바뀌지 않습니다. 긴 요리를 확인하려면 시간 배속 또는 오프라인 건너뛰기를 사용하세요. 실제 결제와 서버 계정은 없습니다.

## 커스텀 데이터

- `src/data.js`: 음식, 캐릭터, 선호 음식, 책, 가구, 성장·의뢰·이벤트 데이터
- `src/assets.js`: 전체 에셋을 ID로 연결하는 25키 중앙 레지스트리
- `src/engine.js`: 순수 게임 상태와 시간 시뮬레이션. UI와 분리되어 Node에서 검증할 수 있습니다.
- `src/render.js`: 쿼터뷰 식당, 경로 이동, 스프라이트·상태 애니메이션
- `src/main.js`: 화면·도감·요리책·편집·저장·테스트 도구
- `public/assets/`: 생성한 PNG 원본과 스프라이트 시트

음식·캐릭터 이름을 바꿀 때 ID는 유지하세요. 저장 파일은 ID로 연결됩니다. 수치 변경은 데이터에서 하고 시뮬레이션 코드는 바꿀 필요가 없습니다. 조리 시간·수량·비용은 참고작의 대응 음식 수치를 사용하며, 판매가·인원 제한 등 복원작 추정치는 초기 밸런스 값입니다. 변경한 콘텐츠 매핑과 미술 방향은 `docs/DESIGN.md`, 생성 이미지 목록은 `docs/ASSETS.md`에 정리했습니다.

이미지는 게임용으로 직접 생성했습니다. 원작 이미지나 음원을 복사하지 않았습니다. 1번 허기진 행인은 별도 그림으로 네 방향 각각 걷기 4프레임과 앉기 1프레임을 사용합니다. 전용 걷기는 이 캐릭터만 적용하며, 학생·배달원·주모·등산객·간호사·직장인 6종은 별도 제작한 네 방향 착석 그림을 사용합니다. 다른 일반 좀비 28종의 전용 걷기는 후속 범위입니다. 계절 손님은 기본 캐릭터 외형을 공유합니다.

## 브라우저 회귀 테스트

개발 서버를 실행한 상태에서 `npm run test:browser`를 실행합니다. Playwright Chromium이 없으면 먼저 `npx playwright install chromium`을 실행하세요. 엔진·악보 단위 테스트 62/62(엔진 60, 악보 2), Playwright 25묶음이 통과했습니다. axe 10회에서 0건, 20개 화면에서 overflow 0건을 확인했습니다. 자세한 결과는 [기획·구현 계획](docs/PLAN.md)을 참고하세요.

혼잡 회귀 검증은 `SOAK_SECONDS=3600 node tests/traffic-soak.mjs`와 `SOAK_SECONDS=3600 SOAK_CLUTTER=1 node tests/traffic-soak.mjs`로 실행합니다. `node tests/traffic-recovery.mjs`는 과거 고착 저장 6종을 각각 1시간 시뮬레이션합니다. `node tests/traffic-ui.mjs`는 통로 안내를, `node tests/visual-seating.mjs`는 방향별 착석 그림 연결을 확인합니다. 이 시뮬레이션은 실제 5시간 자동 플레이와 별개의 시험입니다.

UI는 로컬 NeoDunggeunmo 폰트(라이선스 동봉), bitmap SVG 아이콘, HUD·버튼·메뉴·요리책·알림·설정을 포함한 각진 말풍선 프레임을 사용하며 기존 PNG를 유지합니다. 기존 9개 인터페이스 검토는 범위 한정 Approve이며 직원·손님 충돌 및 서빙대 선택 버그도 기능 검증을 마쳤습니다. 게시 여부는 사이트 배포 기록을 기준으로 확인합니다.

직원은 투명 빈 쟁반을 기본으로 들고, 음식 운반·서빙 작업에서만 음식이 보입니다. 나무 출입문은 닫힌 문 정면 PNG로 왼쪽 벽 쿼터뷰에 투영합니다. 음악을 꺼도 효과음은 계속 재생됩니다.

## 오프라인과 저장

닫기 전 또는 5초 간격으로 저장합니다. 재접속·탭 복귀 시 같은 구간을 중복 계산하지 않습니다. 오프라인은 재고 판매·직원 작업·허기·공격을 최대 8시간 계산하고, 그 이상 경과한 조리·부패·자동 회복 시간은 실제 경과 시간을 반영합니다. 오프라인 판매는 캐릭터북이나 피버를 열지 않습니다.

긴 오프라인 정산은 `src/offline-worker.js`와 `src/offline-startup.js`에서 백그라운드 처리합니다. 시작 안내를 먼저 표시하고 계산 중 원본 저장을 보존합니다. 탭 복귀 시 inert overlay와 게임 시간·Canvas·저장 동결 뒤 게임을 재개하며, 처리 실패 시 기존 복사 방식으로 fallback합니다. 시작·복귀·fallback 검증을 통과했습니다. 본 버전 배포 대상: [테스트 사이트](https://bamsonnim-hanok-zombie.esteemedgrass.chatgpt.site). 실제 배포 상태는 사이트 배포 기록을 기준으로 확인합니다.

브라우저 데이터를 삭제하면 진행이 사라질 수 있으므로 설정에서 JSON 백업을 권장합니다. 브라우저 기반 테스트 게임이므로 기기 시간 변경이나 개발자 도구 조작을 막지 않습니다.
